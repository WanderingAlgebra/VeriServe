所有完整最终 verdict 均为 PASS；两精度的符号错误和零除错误都出现正文、diagnosis 已指出错误，verdict 却为 PASS。BF16 的无效推论题在最终 diagnosis 内容中重复到预算上限。NF4 的除法错误、正确符号展开、正确反例和无效推论四条也在最终字符串内容中重复到上限。截断发生在正文结束后，不能据此抹掉已完成的正文评价，也不能把正文成功当作完整验证接口通过。本轮最终接口没有经过额外 JSON 提示调优；这些格式和字段结果只属于本次固定接口配置。

主对照前发生过一次明确的技术故障：BF16 原始灵活空白配置的前两条正文正常结束，之后在最终 JSON 的空白中重复到 2,048 token。已保留两条完整输出，第三条在途请求中止且没有返回输出，旧源码归档为 [runner_before_compact.py](runner_before_compact.py)。没有把它们混入主对照。

唯一修复是在最终约束启用 `disable_any_whitespace=True`。CPU 回放确认原空白循环被拒绝、正常 JSON 仍可接受。修复后另存 `compact-final/`，固定跑八条 BF16 和八条 NF4，不改提示、种子或输出预算，也不根据质量结果重试。前两条修复前后的 BF16 正文直到 `</think>` 逐 token 一致，见 [repair_consistency.json](compact-final/repair_consistency.json)。该修复消除了所观察到的空白循环，但没有保证最终字符串不重复，因此后续截断全部保留。

主对照 BF16 总输出 3,989 token、请求耗时合计 199.24 秒；NF4 为 10,048 token、626.70 秒。它们输出长度及重复程度不同，不能把这些总耗时直接当作相同输出工作量下的速度比较。计时包含本次 prefill、decode 和结果处理，不含模型加载及 Git 备份；显存为每 20 ms 采样的全设备峰值。逐条输入/输出 token、耗时、峰值、判定和终止状态见 [per_case.csv](per_case.csv)，完整数据见 [summary.json](summary.json)及 [compact-final/](compact-final/)。

本轮没有继续调提示或增加样本。备份故障已经排除；仍需解决的是算术核查不可靠，以及正文检错到最终结构化判决的映射和完成率。现有结果不支持直接把该配置用于后续 17 条或扩大到 57 条。
