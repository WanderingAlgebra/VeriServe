# 验证器替换记录

## 原因与候选

原配置 `Qwen/Qwen2.5-7B-Instruct`（NF4）在首轮 ProcessBench 留出集上，含错前缀的首错精确检出率为 7/25（28%），低于预先设定的 50% 门槛。旧结果保存在 `runs/2549b9dd5d948fe5/`，不覆盖。

本轮选择 [Qwen2.5-Math-PRM-7B](https://huggingface.co/Qwen/Qwen2.5-Math-PRM-7B) 作为候选。官方模型卡将它定义为数学推理的过程奖励模型，并给出在每个 `<extra_0>` 步骤分隔符上提取正确性概率的接口。诊断题继续采用 [ProcessBench 官方数据](https://github.com/QwenLM/ProcessBench) 的原始首错标签。模型 revision、NF4 量化和阈值都写入新配置及运行记录。

它给出步骤分数，不生成自然语言诊断。因此适配器把低分步骤转为 `FAIL` 和通用的“重查该步”提示；这能检验错误定位和通用反馈，但不能证明具体错误解释的质量。JSON 是确定性适配器生成的，格式有效率不代表奖励模型有 JSON 生成能力。

## 隔离与选择

旧诊断开发题保持不变。新的留出题在评分前从其余 ProcessBench GSM8K 案例中固定抽取，排除旧诊断题和 GSM8K 主评估题的规范化题干；ID 固定在 `.cache/splits_prm.json`。只用开发题选择统一阈值：在误报率不高于 20% 的候选中最大化首错精确检出率，平局取离 0.5 最近者。留出题只检查一次，不据其结果调整阈值。原门槛保持 JSON 至少 95%、有效前缀误报至多 20%、含错前缀首错检出至少 50%。

GSM8K 主抽样种子保持方案的 `20260922`。替换验证器时，为从旧诊断题之外新增一份未使用过的 ProcessBench 留出集，额外抽样使用 `20260923`；该偏离原计划的种子已随数据 ID 固定在 `.cache/splits_prm.json`，并发生在新模型评分之前。

新运行使用 `configs/4060_prm.yaml`，不混用旧模型轨迹。未通过门槛时记录 `BLOCKED` 并停止依赖的反馈正式评估。

容量预检显示该 PRM 的 NF4 版本在 2048 token 输入下剩余约 2.14 GiB 显存，因此新正式配置恢复方案最初的 2048 token 上下文上限。先前短暂启动的 1024 token 新模型运行保留在独立目录，只作容量预检，不与正式结果合并。
