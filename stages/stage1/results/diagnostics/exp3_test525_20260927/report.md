# 实验三 test-525 缓存差异诊断

日期：2026-09-27。标签：`DIAGNOSTIC_ONLY`。本记录用于解释已发现的不一致，正式 BF16 运行的 `BLOCKED_A` 状态保持不变。

## 结论

本例对照支持：BF16 下，计算序列长度和分块方式不同引入数值差异；候选 token 的分数接近时，舍入和平分选择导致 greedy 续写分叉。直接裁剪操作完整保留了应保留的缓存张量。当前证据不支持将本例直接认定为缓存边界删错；也不能凭单例诊断证明整个缓存实现无误。

## 怎样复测

使用正式运行 `3660363ff392fea6` 的 `states/exp2b_eval/k2/test-525.json` 中第一个自然 FAIL 快照，沿用固定生成器 revision 和已保存的 token。保留前缀 255 token，被拒后缀 94 token，反馈 61 token。生成器是 Qwen2.5-1.5B-Instruct，使用 greedy，无随机采样，也不重新调用验证器。

- A：先处理前缀＋被拒后缀，裁掉后缀，再处理反馈。
- B：一次处理前缀＋反馈。
- D：只处理前缀，再处理反馈；全程不裁剪。D 是本次诊断新增对照，与正式 B/C 中的 C 无关。
- 先复现原始一致性检查，再记录三个计算路径的逐 token 选择；最后将同一套已加载权重转为 FP32，重复诊断。

## 实测结果

原始检查再次得到 `greedy_equal=false`，追加反馈后的最大 logits 差仍为 `0.28125`，与归档结果一致。

BF16 的 A/B 在前 16 个续写 token 完全一致，第 17 个开始分叉：

| 计算方式 | ` If` 分数 | ` She` 分数 | 实际选择 |
| --- | ---: | ---: | --- |
| A：裁剪后复用 | 22.625 | 22.625 | ` If`，平分时由 argmax 选择 |
| B：完整重算 | 22.5 | 22.625 | ` She` |

共同开头为 `Step 3: Heather has 27 cups of raisins in total.`，A 接着生成 ` If she divides...`，B 接着生成 ` She wants to divide...`。这次检查只比较 32 个 token，不能据此判断两种完整解答最终是否一对一错。

| 对照项目 | BF16 | FP32 |
| --- | ---: | ---: |
| A/B 追加反馈后的最大 logits 差 | 0.28125 | 0.00004863739013671875 |
| A/B 32 token 完全一致 | 否 | 是 |
| D/B 32 token 完全一致 | 是 | 是 |
| 裁剪结果与裁剪前应保留的 K/V 张量逐值一致 | 是 | 是 |
| 从较长序列截取的前缀 K 与只处理前缀所得 K 的最大差 | 1.0 | 0.00003731250762939453 |

这说明差异在前缀缓存的计算阶段就可能出现；本例的裁剪操作本身没有改坏保留的数值。提高计算精度后差异显著缩小且分叉消失，支持数值精度解释。尚未进一步定位到具体层、矩阵乘内核或 attention 内核。

PyTorch 官方说明：数学上等价的浮点运算在计算顺序、批次或切片方式不同时，不保证逐位相同。参见 [PyTorch 2.9 Numerical accuracy](https://docs.pytorch.org/docs/2.9/notes/numerical_accuracy.html)。

## 结论边界与复现

这里只诊断一个失败案例。FP32 是额外诊断条件，没有替换正式 BF16 配置，没有重跑完整十例门槛，也没有证明 FP32 在后续双模型服务中的容量和速度可用。因此不能据此把正式缓存状态改为通过。
